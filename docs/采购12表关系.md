# 采购询价 12 张表的关系（用真实数据验证过）

> 结论都可以用 `python scripts/try_relations.py` 复现。

## 一、怎么判断"一对多"（三步，不用背）

1. **找主键**：`DESC 表名`，`键` 那列是 `PRI` 的字段，它的值一定唯一 —— 这就是关系里的「1」那头。
2. **看子表**：子表里存着主表的某个值，同一个值会出现很多次 —— 这就是「多」那头。
3. **数一数确认**：主表该字段「去重数 == 总行数」才算唯一；否则它不能单独当「1」。

## 三、三个必须记住的坑（都是实测发现的）

1. **主键名和文档不一致**：`biz_purchase_order_item` 的主键叫 `order_item_id`，不是文档写的 `id`。文档 4.10 写"关联 biz_purchase_order.order_id"也是错的，实际 `order_item_id` 指向明细表。
2. **业务编码单看一定重复**：`jd_supplier.number` 3716 行只有 1863 个不同值，因为库里有 2 个租户（1863 + 1853）。所以**任何一个 join 都要带 `tenant_id`**，否则跨租户数据会互相串，行数翻倍。
3. **不是所有编码都能匹配上**：明细→物料 1054 个编码里 1032 个命中，物料分类→供应商对应 332 个里 325 个命中。历史数据或跨租户会漏，所以调试时先用 `LEFT JOIN` 看漏了哪些，别直接 `INNER JOIN` 就以为查全了。

## 四、一条能跑通的三表链路（询价单 → 物料行 → 各家报价）

```sql
SELECT o.order_id, i.number, i.qty, s.supplier_code, s.quote_price
FROM biz_purchase_order o
JOIN biz_purchase_order_item i
     ON i.order_id = o.order_id AND i.tenant_id = o.tenant_id
JOIN biz_purchase_order_item_supplier s
     ON s.order_item_id = i.order_item_id AND s.tenant_id = i.tenant_id
LIMIT 5;
```

实测结果：`XJD-000000-260814-0001` / `XAAA01-0001` 下挂着 `G0987654321`、`G123456789`、`G987654321` 三家供应商 —— 这正是「一个物料行，多家报价」的一对多。

## 五、文档里那句话怎么读

文档写「通过 `billno,tenant_id` 关联 `jd_purapply_order.billno,jd_purapply_order.tenant_id`」，
翻译成人话：**这张表（子表）的 `billno` + `tenant_id` 两个字段合起来，指向对方表的 `billno` + `tenant_id`**。
写 SQL 就是：

```sql
... JOIN jd_purapply_order p ON c.billno = p.billno AND c.tenant_id = p.tenant_id
```
